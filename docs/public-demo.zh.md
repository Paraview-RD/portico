# 发布一个陌生人能用的 demo

[access-guide.md](access-guide.md#发布一个任何人都能打开的演示环境)
讲的是把演示环境放上 Render、把地址交给别人。这一页是剩下的部分：一个自己的域
名、能进别人收件箱的邮件，以及自助试用 —— 也就是「一个我能演示的 demo」和「一
个谁都能自己走进来的 demo」之间的差别。

下面的顺序不是偏好。其中四步做反了会得到一个**看起来完全健康、而且没有任何东西
会报错**的部署，这几步都标出来了。每一步动手之前先读完它。

## 一个域名，两份工作

对外的地址和发信的地址应该是同一个注册域名，理由不是整齐：一台从没见过你的接收
方邮件服务器会把它能找到的一切都拿来称量，而**一个同时在 HTTPS 上跑着真实网站的
发信域名，看起来像一个组织**，而不像今早刚注册来发一轮广告的名字。

这里面还剩一个决定：**从子域发信** —— `mail.example.com` —— 而不是从根域，公网
地址再放另一个子域 `demo.example.com`。发信信誉挂在签名的那个域名上，所以用子域
可以让 demo 邮件某一周的糟糕表现，不跟着根域走到你下一次用它的地方。两种都能用，
这一种是比较不会后悔的那种。

## 挑注册商

`.com` 的价格彼此差不了几美元。真正有差别的是**你要交出多少关于自己的东西**，以
及 DNS 是不是在一个你半夜两点还愿意打开的地方。

**注册信息不是可选项。** ICANN 要求每个通用顶级域都登记姓名、通信地址、邮箱和电
话，没有注册商能豁免。有差别的是**谁能看到**：WHOIS 隐私保护会用注册商自己的信
息替换掉公开记录里的你，下面这几家都是免费且默认开启。所以「信息越少越好」这件
事，问的其实是**验证**，不是那张表单。

而最大的差别正在这里。**受中国监管的注册商要求实名认证** —— 上传证件、比对通过，
域名才会解析。那不是一笔费用或一次延迟，是另一个性质的东西。如果你想避开的是这
个，那么在比价之前决定就已经做完了。

在「只要一个邮箱和一种付款方式」的注册商里：

| 注册商 | 为什么在这张表上 |
| --- | --- |
| **Cloudflare Registrar** | 按成本价卖 —— 没有首年折扣也没有续费加价，所以那个数字一直是那个数字。WHOIS 隐私始终免费开启。DNS 就在同一个面板，这一点在这里重要，因为你接下来要加四条记录，而且希望它们在同一个地方。代价是它不允许 DNS 放在别处。 |
| **Porkbun** | 价格相当，WHOIS 隐私免费，DNS 品质在这个价位里少见地好，而且没有一路要点掉的推销。如果你希望域名和 DNS 以后能分开，选它。 |
| **Namecheap** | 更大、更老牌，多数 TLD 的 WHOIS 隐私免费。如果你本来就有账号，值得；否则在这件事上和 Porkbun 没有可分辨的差别。 |

三家都是五分钟左右能走完。这一页假定的是 Cloudflare，因为把注册和 DNS 放在同一个
账号下，可以去掉「记录加错了面板」这一步。

### 顶级域

对于一个**工作是把邮件投递给从没听说过你的人**的域名，`.com` 是保守的选择。更新
的 TLD 更便宜也更好看，同时在一部分过滤器里带着更弱的默认信誉 —— 因为大量一次性
发信发生在它们上面。这是一条经验而不是一次测量（过滤器不公布权重），但**猜错的代
价是一封确认邮件悄无声息地没有到达**，而这正是整页文档想避免的那一种失败。

## 步骤

### 1. 注册域名

别的都做不了。注册后通常几分钟内解析生效；如果注册商同时是 DNS 托管方，就是立刻。

### 2. 在邮件服务商那里验证域名 —— 在任何别的东西需要它之前

在服务商后台添加域名，把它给的 DKIM、SPF、DMARC 记录加进 DNS，等它变成已验证。

**这是那个会无声失败的步骤。** 域名未验证时，服务商通常**仍然让你发信** —— 从它
自己的公共地址，发给**拥有这个账号的那个邮箱**。于是你对自己做的每一次测试都成
功，发给任何其他人的每一封都被拒绝或丢弃，而应用两种情况下都记录为发送成功。**只
对着自己的收件箱验证过的 demo，等于没验证过。**

DMARC 从 `p=none` 开始。它只索取报告，不要求接收方拒收 —— 这正是一个从没发过信的
域名需要的：在一个配置还不对的域名上写 `reject`，拒掉的是你自己的邮件。

### 3. Apply Blueprint

Render → New → Blueprint，指向你的 fork，`render.yaml` 在仓库根。如果新加坡不是
最近的区域，**先改 `region`** —— 服务建好之后无法迁移。

**先别开试用。** 它有个前提在第 6 步之前不成立，提前打开会得到一个必然失败的按钮。

Render 会问三个值。`PORTICO_ENCRYPTION_KEY` 是 32 字节十六进制，`openssl rand
-hex 32` 生成。`PORTICO_INITIAL_ADMIN_PASSWORD` 是等不了的那个 —— 地址从部署那
一刻起就是公开的，而不填就意味着 `admin` 账号是用手册里公开写着的那个密码创建
的。`PORTICO_PUBLIC_URL` 先填 Render 给的 `onrender.com` 地址，第 5 步再换成真的。

### 4. 把域名指向服务

Render → 服务 → Settings → Custom Domain → `demo.example.com`，它会给一条 CNAME，
回注册商那里加上。

**如果 DNS 托管方会代理流量 —— Cloudflare 的橙色云 —— 给这条记录关掉它。** 在代
理后面 Render 无法完成签发证书所需要的验证，症状是：域名能解析、能应答，而**每个
浏览器都说它不受信任**。

### 5. 把 `PORTICO_PUBLIC_URL` 改成真实地址

`https://demo.example.com`，然后重新部署。

**这一步值得停下来看一眼。** 服务器写进邮件的每一个链接都由这个值拼出来，OpenID
Connect 的跳转和 SAML 元数据也是。它还指着旧地址时，控制台一切正常、邮件发送成
功，**唯一坏掉的是信里的那个链接** —— 而那是收信人唯一能操作的东西。没有任何东西
会报告这件事：不会出错，地址只是错的。

### 6. 给它一条发信通道

在 Render 免费实例上这条通道不能是 SMTP：出站 25、465、587 都被封，症状是连接超
时，改任何中继设置都不管用。用 HTTP 通道：

```
PORTICO_MAIL_TRANSPORT   resend
PORTICO_RESEND_API_KEY   一个只能发信的 key
PORTICO_MAIL_FROM        portico@mail.example.com
```

`PORTICO_MAIL_FROM` **必须在第 2 步验证过的域名下**。其他域名的发件人会被服务商拒
绝，而不是被 Portico 拒绝。

付费实例上 SMTP 在 465 和 587 可用，`PORTICO_SMTP_*` 那组键在 `render.yaml` 和
[access-guide.md](access-guide.md#然后如果你要开自助试用) 里都列着。

### 7. 打开三个开关

```
PORTICO_TRIAL_SIGNUP     true
PORTICO_LANDING_PAGE     true
PORTICO_TENANT_CONSOLE   true
```

相对第 6 步而言必须在它之后。没有中继时，试用会用 `TRIAL_MAIL_UNAVAILABLE` 拒绝
每一个请求。

主页开关让根地址不再是登录表单 —— 那正是陌生人需要的，**登录表单向他要的是他没有
的东西**。租户控制台是你在不打开任何租户的前提下看见都创建了什么的地方，只对默认
租户的管理员可见。

### 8. 让它别睡，并且知道它什么时候会死

把 `DEMO_URL` 加成 Actions 的 **variable**（不是 secret），值为公网地址。没有它，
`.github/workflows/demo-keepalive.yml` 会照常运行并且什么都不做 —— 那看起来和正常
运行一模一样。

然后在**不是这个仓库**的地方记两个日期：

- 免费 Render 实例十五分钟无流量就休眠。保活刻意只覆盖工作时段：一个月 750 实例
  小时不够全天候醒着。窗口之外，第一个访客要等冷启动。
- **免费 Postgres 在创建三十天后过期，另加十四天宽限期。** 所有试用租户连同里面
  的一切一起消失，Blueprint 要重新 apply 一遍。**没有任何东西会提醒你。**

### 9. 用一个不是你的身份测一遍

用一个**你控制不了的邮箱**申请试用 —— 同事的，或者一次性邮箱。然后在那一侧读信，
把链接走到底。

这是唯一有意义的测试，也是第 2 步排在那个位置的原因。**在一个谁也发不到的部署上，
发给自己是会成功的**，因为服务商把账号所有者当特例。到这里为止的每一步都可以靠看
来验证，这一步只能靠一个不是你的人来验证。

## 走完之后应该看到

- 根地址说明这是什么，并给出两条路。
- 一个陌生人申请试用，一分钟内收到邮件，在收件箱而不是垃圾箱。
- 信里的链接创建出租户，第二封信里的凭据能登录。
- 以默认租户管理员的身份打开 `/tenants`，能看到已经存在的东西。

如果第一封信没到，答案几乎总是第 2 步或第 5 步 —— 域名从来没验证过，或者链接指向
一个已经不存在的地方。

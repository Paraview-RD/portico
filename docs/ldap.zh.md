# 从目录读取

Portico 会连接你的 Active Directory 或 OpenLDAP，把账号拉过来——手动触发，或按你
设定的间隔自动进行。这与
[目录供给](scim.md) 是**相反的方向**，而这个区别值得记牢——因为两者最终落在
同一个地方：

| | SCIM | LDAP |
|---|---|---|
| 谁发起 | 目录 | Portico |
| 在哪里配置 | 在目录里，指向 `/scim/v2` | 在这里，**目录对接** |
| 账号不再进来时 | 这一端没有任何东西可看 | 有一次失败的执行记录，附原因 |
| 谁保管凭据 | 目录保管这里签发的令牌 | Portico 保管一个 bind 密码 |

如果你的目录能推 SCIM，优先用它：这样这里根本不需要保存任何关于服务账号的东西。
LDAP 之所以存在，是因为大多数 Active Directory 部署做不到推。

## 同步内容

用户。不同步组，不同步组织，不同步密码。

- 出现了这个数据源此前没见过的条目 → **新建**。数据源可以指定一个组织，它新建的账号
  会归到那里。**这也是它唯一一次生效**：之后的同步不会把管理员挪走的人再挪回去——目录
  说的是这个人是谁，而他归在哪里，由这一侧决定。
- 显示名、邮箱、电话或用户名变了 → **更新**。
- 某个条目不再出现 → **停用**。
- 它又出现了 → **重新启用**——一个作为事实源的目录，必须能说"这个人回来了"。

**密码从不被读取，也从不被写入。** 从目录同步进来的账号在这里持有一个随机密码，
没有任何东西能用它通过认证，与 SCIM 供给进来的账号一样。**用 AD 密码登录是另一
个功能**（联邦，不是同步），目前不存在。

## 属性映射

**没有默认值，而且这是刻意的。** Active Directory 和 OpenLDAP 在下面每一项上都
不一致，而一个错误的猜测会导入一整个目录、每个账号都以错误字段命名——**它看起来
和一个正常工作的集成一模一样**，直到有人真的去读用户列表。

| | Active Directory | OpenLDAP |
|---|---|---|
| 用户过滤器 | `(&(objectClass=user)(objectCategory=person)(!(userAccountControl:1.2.840.113556.1.4.803:=2)))` | `(objectClass=inetOrgPerson)` |
| 用户名 | `sAMAccountName` | `uid` |
| 显示名 | `displayName` | `cn` |
| 邮箱 | `mail` | `mail` |
| 电话 | `telephoneNumber` | `telephoneNumber` |
| **外部标识** | **`objectGUID`** | **`entryUUID`** |

控制台把两套都做成了预设。它们只是**把字段填好并保持可编辑**——请对照你自己的
目录核对，而不是信任它们。

上面那条 AD 过滤器排除了已禁用的账号。如果你更希望它们也进来、然后由它们的
`userAccountControl` 值把它们停用，就把这一段去掉；Portico 自己不读这个属性。

### 外部标识

它是对账键。**其它每一项错了都还能事后修正；这一项错了，意味着目录里的每一次改名
都会在这里创建第二个账号，而不是把第一个改名**——静默发生，且事后无法合并。

`objectGUID` 是**二进制**的：十六个原始字节，Portico 按微软自己的混合字节序 GUID
形式渲染，所以你在这里看到的与 `Get-ADUser` 以及其它任何工具显示的一致。
`entryUUID` 本身就是文本，按收到的样子存储。

**不要**把它指向 `distinguishedName` 或 `userPrincipalName`。这两个都会在有人调岗
或结婚时改变。

## 同步范围限制

**它不会对空结果采取行动。** 一次什么都没匹配到的搜索，看起来和"一个所有人都已
离开的目录"完全一样。前者是 base DN 或过滤器里的一个笔误，经常发生；后者基本不会
发生，而且没有人会希望它在夜里被自动执行。所以一个**拥有账号的数据源却什么都没拿
回来时，本次执行失败、什么都不改**。

**它不会碰不属于自己的账号。** 归属是被记录下来的，不是从用户名推断的。一个碰巧
与目录里某人同名的管理员会被跳过——不改名、不降权，之后那个目录条目消失时也不会
被停用。执行记录里的"跳过"计数就是这些账号出现的地方。

**它不会删除。** 账号被停用，与 SCIM 的 `DELETE` 语义完全一致，这样审计轨迹指向的
东西始终存在。

**停用连接器不会停用它的账号。** 连接器和人是两回事。用它来停止同步——比如目录
迁移期间——而不必把任何人挡在门外。

## 关于 bind 密码

这是本系统中唯一一个**必须可还原、而不是只需可校验**的凭据：Portico 每次执行都要
把它发给你的目录。

它用 AES-256-GCM 加密，密钥来自 `PORTICO_ENCRYPTION_KEY`，而这个密钥在环境变量里
而不是数据库里。诚实地说明它的边界：**任何能读取进程环境的人都能读到这个凭据。**
它防的是真正会发生的那种泄露——一份备份、一个副本、一个为了排障交给别人的快照。

**没有设这个变量时，Portico 拒绝保存 bind 密码**，而不是明文写下去。用
`openssl rand -hex 32` 生成一个，并且**不要复用 `PORTICO_JWT_SECRET`**——服务器
同样会拒绝，因为一个值干两份活意味着任一处泄露都要付两份代价。

请使用**只读**服务账号。Portico 从不向你的目录写入，一个有写权限的 bind 账号是一
份没有任何收益的长期风险。

Bind DN 留空表示匿名绑定，某些只读目录允许这样。

## 同步操作

手动：**目录对接** → **同步**。执行是同步进行的，并报告它做了什么——新建、更新、
停用、跳过——而且**按次保留历史**，因为出问题时人们问的不是"现在是什么状态"，而是
"这是从什么时候开始的"。

自动：同一张表单上的**自动同步**，从每 15 分钟到每周一次。**默认是关的**，所以不会
因为升级了 Portico 就有谁开始读你的目录。

**不要再去搭那个 cron 任务了**。它曾是本页记录的替代方案，而且比看上去更糟：
`POST /api/v1/directories/{id}/sync` 需要访问令牌，令牌有效期是 `PORTICO_TOKEN_TTL`
（默认两小时），并且会被改密码或"退出所有设备"吊销——所以这个任务每次执行都得先
登录，也就意味着**一个管理员的密码躺在 cron 的环境里**。那是一个比本页花了一整节
去保护的 bind 密码更糟糕的凭据。调度器跑在服务进程内部，**根本不持有任何凭据**。

### 同步调度行为

**开启时会立刻跑一次**，而不是等满第一个间隔。否则你配好一个"每天凌晨同步"，要到
第二天才知道自己有没有配对。

**失败的一次会等到下个间隔**，不会在下一个 tick 就重试。否则一个指向已经消失的主机
的源，只要一直坏着，就会每分钟去连它一次——那正好是间隔存在的意义的反面。

**失败的一次不会改动「上次同步」**。那一列回答的是"这个目录还是不是权威来源"，
如果每次尝试都推进它，一个已经坏了一周的对接会显示成"两分钟前刚同步过"。看那一列
是最近一次**成功**，看执行历史是这期间到底发生了什么。

**定时执行不归属到任何人**。历史里显示为**定时任务**，而不是记在最后编辑这个对接的
人头上——那些账号不是他停用的。

**两个 Portico 实例对同一个目录，一共只跑一次**。谁先领到谁跑，另一个发现已被领取
就跳过。不需要配置，也不需要在第二个实例上关掉什么。

15 分钟这个下限不可调。一次同步只有一种规模——要知道谁离开了，就得把目录里所有人
都列一遍——所以更短的间隔不是更新鲜的数据，而是**对别人的 LDAP 服务器做压力测试**。
超出允许范围的间隔会被**拒绝而不是取整**，所以表单上写的就是实际在跑的。

**重启不会有代价**。目录是在**即将读取之前**才被领取的，而不是在一轮开始时就全部
领走，所以中途重启时，那些还没轮到的目录**仍然是到期状态**——一分钟内就会被接上，
而不是为一次根本没发生的同步白等一个间隔。

有两件事值得知道它**不做**。**定时执行和手动点「同步」可能重叠**：领取机制防的是
多实例互撞，不是防人在执行中途去点按钮。还有，**进程停止时正在飞行的那一次会以
`RUNNING` 留在历史里**——它的尝试是**刻意**在联系目录之前就记下的，所以那个目录的
下一次尝试是一个间隔之后，而不是立刻。

## 排查

**"No Such Object"** —— base DN 不存在。注意这是**目录自己的措辞，刻意不做翻译**：
它是值得拿去搜索的那个字符串。

**执行失败，提示目录没有返回任何条目** —— base DN 存在，但过滤器没匹配到人。先查
过滤器；正是这条拒绝阻止了所有人被停用。

**账号进来了但名字不对** —— 显示名属性指错了字段。改好再同步一次；已存在的账号会
就地更新。

**一次改名产生了第二个账号** —— 外部标识属性指向了一个会变的东西。在它再次发生
之前停止同步。

**跳过数不为零** —— **这次执行会说明原因**，按原因归组并各给一个例子：
`5 × That is not a valid phone number. (mei, arjun, …); 1 × That username is
already in use. (admin)`。先读它，再去猜。

最常见的一种是**与 Portico 自己拥有的账号发生的用户名冲突**，不是目录的毛病。其余
是没有用户名、没有外部标识的条目，以及账号规则拒绝的值——**一个按人类习惯带空格
书写的电话号码**，是最常绊住人的那一个。

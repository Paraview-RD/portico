# 外部依赖

本项目在运行时依赖的第三方平台、API 与服务。

## 运行时服务

### PostgreSQL —— 必需

唯一的硬依赖。测试用的是 17 版；14 及以后应该都能用。

早期版本把所有东西存在一个 SQLite 文件里，那让一次部署等于一个进程加一个卷。多租户
和面向公网的 SSO 改变了这个权衡：**隔离需要真正的约束，而单写者数据库对一个依赖其可用性的身份提供方来说是错误的形状。**

完全通过 `PORTICO_DB_DSN` 配置。**没有默认值**——他人数据库的连接字符串无法猜测。

### SMTP —— 密码找回与注册确认所必需

两者都要发消息，所以都需要一条能发出去的通道；**一个要求新账号确认地址的租户，在没有
配置中继时无法打开那个开关，并且会在打开的那一刻被告知**。Portico 讲的是标准 SMTP，
而不是某个厂商的 SDK：一个自托管的部署应该能指向它本来就在跑的任何东西——公司中继、
Amazon SES、Postmark、Resend，或者一个本地 Postfix。

**没有需要注册的厂商账号，本项目也不持有任何 API key。**

| 配置项 | 含义 |
|---|---|
| `PORTICO_SMTP_HOST` | 中继主机名。为空表示邮件找回不可用，这是默认值。 |
| `PORTICO_SMTP_PORT` | 默认 `587`。 |
| `PORTICO_SMTP_USERNAME` / `PORTICO_SMTP_PASSWORD` | 两个都不填表示不认证直连，这对私有网络里的中继是常态。 |
| `PORTICO_SMTP_FROM` | 信封与信头的发件人。一旦设了 host 就必填。 |
| `PORTICO_SMTP_ENCRYPTION` | `starttls`（默认）、`tls` 或 `none`。 |
| `PORTICO_PUBLIC_URL` | 那些消息里的链接指向哪里。 |

**STARTTLS 是强制的，而不是"尽力而为"的。** 尽力而为的 STARTTLS 可以被路径上的任何
人剥掉，而这些消息里带着密码重置链接——**一次静默降级就是全部的威胁**。

**任何凭据都不属于这个仓库。** `.env.example` 里只有变量名。

### Resend

可选，不主动开启。**SMTP 仍然是默认，也仍然是自己有中继的人的正确答案。**

它存在的理由是：小型部署付得起的托管环境里，有相当一部分根本不允许进程打开 SMTP
端口。Render 的免费实例封了出站 25、465、587；25 端口在付费实例上也依然封着，绝大
多数云厂商同样如此。**表现是连接超时**——所以中继配置里没有任何一处是错的，调整任何中继配置均无效。而 HTTPS 哪里都没封，这就是全部的论据。

设 `PORTICO_MAIL_TRANSPORT=resend`，同样的消息改走
`https://api.resend.com/emails`。邮件接口以上的东西一律不变。

| 配置项 | 含义 |
|---|---|
| `PORTICO_MAIL_TRANSPORT` | `smtp`（默认）或 `resend`。 |
| `PORTICO_RESEND_API_KEY` | 一个 Resend API key。**只发信权限的 key 就够了，也应该用这种**——这里不读取、不列举任何东西。 |
| `PORTICO_MAIL_FROM` | 发件地址，域名需已在 Resend 完成验证。 |

- **用途**：在封了 SMTP 的主机上，发出密码找回、地址确认和试用相关的邮件。
- **认证**：bearer API key，在 Resend 控制台生成。
- **账号归属**：部署方自己。本项目不持有 Resend 账号，也不内置任何 key；公开演示环境
  的 key 属于它的运维者。
- **成本**：撰写本文时免费额度为每月 3000 封、每天 100 封，比一个演示环境需要的多。
  超出后按量付费。

**没有验证过的域名时，Resend 账号只能以 `onboarding@resend.dev` 为发件人，且只能发给
注册该账号的那个邮箱。** 这足够把流程完整走一遍，但不足以支撑任何真实用途——要给别人
用的部署，得先验证一个域名。

两个配置项都在启动时校验：选了这个通道却没给 key 或发件人，是配错了，而不是"这个部署
选择不发邮件"。

### 短信 —— 可选

用手机号找回密码需要一个短信网关，而与邮件不同，它没有一个通用协议。Portico 定义了
一个小的 provider 接口；由部署方提供实现，或者干脆关掉短信、只用邮件。

*状态：接口和一个空实现存在；具体的 provider 尚未编写。*

### Active Directory / OpenLDAP

目录连接器会从一个 AD 或 OpenLDAP 里读账号。**它是唯一一个由 Portico 打开连接、去连
别人运行的系统的集成，也是唯一一个 Portico 要保存一份"日后还要拿来用"而不只是"用来
校验"的凭据的集成。**

没有厂商账号、也没有东西要买：那是你自己的目录，而要用的账号是你在里面创建的一个
**只读服务账号**。Portico 从不向你的目录写入，所以**一个有写权限的 bind 账号是一份
没有任何收益的长期风险**。

| 配置项 | 含义 |
|---|---|
| 服务器地址、bind DN、bind 密码、base DN、过滤器、属性映射 | 按连接器配置，在控制台 **目录对接** 里——**不是环境变量**，因为一次部署可能有好几个。 |
| `PORTICO_ENCRYPTION_KEY` | 32 字节十六进制。凡是**必须可还原、而不是只需可校验**的凭据，都用它做 AES-256-GCM 封装：目录的 bind 密码，以及 webhook 订阅要发送的自定义头的值。**不设它时，这两样的保存都会被拒绝**，而不是明文存下去。必须与 `PORTICO_JWT_SECRET` 不同。 |

诚实地说明那层加密的边界：**任何能读取进程环境的人都能读到这个凭据。** 它防的是真正
会发生的那种泄露——一份备份、一个副本、一个为了排障交给别人的快照。

**它是一个数据源，不是一条登录路径。** 密码从不从目录读取、也从不写入目录；一个同步
进来的账号**无法**用它的 AD 密码通过认证。联邦登录是另一个功能，目前不存在。
[从目录读取](ldap.md) 里有属性映射表，以及一次同步**拒绝**做什么的清单。

### Prometheus

设置 `PORTICO_METRICS_ADDR` 会打开第二个监听，以文本暴露格式发布指标。**没有账号、
没有令牌，除了地址之外没有任何配置**：Prometheus 来抓 Portico，所以什么都不会被发出
去，也不持有任何凭据。

**方向就是要点。** 这不是遥测——除非你网络内部有东西过来读，否则什么都不会出去；而
如果你从不设那个地址，这个监听根本不存在。为什么它是一个独立端口，见
[访问指南](access-guide.md#指标)。

## 演示环境托管

下面这些都**不是** Portico 的依赖，而是**我们**跑那个公开演示环境的地方。记在这
里，是因为总得有人知道账单挂在哪、以及谁能连到那个数据库。

### Render —— 公开演示环境，免费层

| | |
|---|---|
| 用来做什么 | `render.yaml`：一个由 `deploy/Dockerfile` 构建的 web 服务。数据库在 Neon，见下一节 |
| 认证方式 | 持有这份 Blueprint 的 Render 账号。本仓库里不存任何 token |
| 归属 | 仓库所有者 |
| 成本 | **$0。** 代价是下面那一条 |
| 环境变量 | `PORTICO_JWT_SECRET`（自动生成），以及需要手填的 `PORTICO_DB_DSN` / `PORTICO_ENCRYPTION_KEY` / `PORTICO_PUBLIC_URL` —— 见 `render.yaml` 里的注释 |

**免费的 web 服务在 15 分钟无流量后会休眠。**
`.github/workflows/demo-keepalive.yml` 每五分钟问它一次 `/api/v1/health`，
**但只在 UTC 00:00–11:00 之间** —— 也就是 +08 的 09:00 到 19:00，前面多留了一小时
预热：如果第一次戳落在 09:00，第一个访客付的正好是它想避免的那次冷启动。

**限定时段不是为了省 Actions 时长**（那是免费的），是为了省 Render 的：免费
workspace 每个日历月有 750 实例小时，而**一个 24 小时不睡的服务要花掉约 730 小时**
—— 能用，但把额度用得一点不剩，再开第二个免费服务、或者赶上一个有重新部署的月份就
不够了。每天十一小时约合 340 小时。

**这五分钟来自 `sleep`，不是来自 cron。** GitHub 的调度是尽力而为的。这个工作流
的第一版让 cron 每十分钟跑一次，结果一次都没能让服务保持唤醒：实测一整天，**要求
66 次，实到 12 次**，间隔 27 到 69 分钟。到 2026 年 10 月，变成了一天三次，有的在
窗口关闭几个小时之后才到。

所以现在定时任务只负责**启动一次运行**，由这次运行按自己的时钟一直戳到窗口关闭。
cron 从 UTC 22:07 到 10:07 每小时一次，一天十三次机会：窗口开之前启动的会等窗口打
开，窗口关之后才到的直接退出，前一次还在运行时到达的会排在它后面等着。GitHub 限制
单个 job 最长六小时，所以十一小时的窗口由两次运行接力完成：第一次在 345 分钟时自行
结束，排队的那一次接上。

剩下的风险在 GitHub 本身：如果某天十三次触发没有一次及时到达，那个上午就是冷的。五
分钟间隔的外部定时服务（cron-job.org、UptimeRobot）不依赖 GitHub 的队列，代价是多
一个账号；Render 的 $7/月 档位则根本不休眠。

**运行变红，表示演示环境连续三次没有应答。** 2026 年 10 月 Render 数据库过期时，它
几小时内就变红了，然后红了一个星期，没人看到。要么盯着 Actions 页面，要么让 GitHub
的定时任务失败通知发到一个有人看的邮箱。

`DEMO_KEEPALIVE=off` 可以停掉这个定时任务；**手动触发该工作流仍然会去检查一次。**

### Neon —— 公开演示环境的数据库，免费版

| | |
|---|---|
| 用来做什么 | Render 服务背后的 Postgres，通过 `PORTICO_DB_DSN` 连接 |
| 认证方式 | 持有该项目的 Neon 账号。连接串存在 Render 面板里，不在本仓库 |
| 归属 | 仓库所有者 |
| 成本 | **$0。** 每个项目 1GB 存储、每月 100 计算小时 |

不用 Render 自带的 Postgres：它的免费版创建三十天后过期，过期后除非升级，否则读不
了 —— `pg_dump` 也不行 —— 再过十四天就被删除。所以演示环境以前每个月要重建一次，
每次都丢光所有数据。Neon 的免费版不会过期。

它的代价是空闲五分钟后挂起，下一次连接时一秒内唤醒 —— 和服务自己的冷启动相比可以
忽略。挂起的时间不计入计算小时，所以每月的额度只在有人使用演示环境时消耗。

项目在 AWS Asia Pacific (Singapore)，与服务同区；用的是直连串而不是连接池串：服务
启动时跑迁移，需要一个独占的会话。

### GitHub Actions

定时任务在 Render 上是付费功能，而公开仓库的 Actions 时长不计量，所以这两件事放
在这里。

`demo-keepalive.yml` 请求健康检查端点。**只有这一个**定时任务，实际上也一直只有它
真正运行过。

原本还有一个 `demo-reseed.yml`，每晚清空 schema 重新灌种子。它已经删掉了，而顶替它
的不是另一个定时任务：试用创建的租户现在自带期限 —— 14 天，再加一周宽限 —— 所以那
些原本要被清扫的东西会**按每个租户各自的时钟自己清掉**。不再需要任何东西从外面伸手
进数据库。

| Secret / 变量 | 是什么 |
|---|---|
| `DEMO_URL`（变量，不是 secret） | 那个公开地址。设成 secret 会被从日志里涂掉，而日志是这个任务唯一的产出 |
| `DEMO_KEEPALIVE`（变量，可选） | 设成 `off` 即停掉保活的定时任务，删掉即恢复。**手动触发那个工作流仍然会去检查** —— 保活关着的时候，正好只剩这件事值得做 |

## 全部运行时依赖

没有消息队列、没有缓存、没有对象存储。**也没有外部身份提供方**：上面那个目录是被
**读取**账号的，从不被要求为任何人做认证，所以**没有任何一次登录会离开这个系统**。

**什么都不会主动往外报。** Portico 只发起三类出站连接，且全都指向你配置的地址：你的
数据库、你的 SMTP 中继，以及一个你指定的目录。Webhook 加上第四类，指向租户管理员注册
的目的地——限定为公网 HTTPS，并在建立连接时再校验一次，所以它们无法被瞄准内网。指标
端点由你的监控来读，从不被推送出去。

## 新增集成

如果将来某次改动引入了一个外部依赖，**在同一个提交里**把它加到这里，写清：它是做什么
用的、怎么认证、账号归谁、成本多少、需要哪些环境变量。同时把那些变量加进
`.env.example`。

## 构建期依赖

它们不是第三方**服务**，但因为影响部署形态，值得点名。

| 依赖 | 为什么重要 |
|---|---|
| `github.com/jackc/pgx/v5` | PostgreSQL 驱动，经 `database/sql` 使用。纯 Go，所以二进制仍可自由交叉编译，并能在没有 libc 的 `scratch` 容器里运行。 |
| `github.com/wneessen/go-mail` | 构造并发送找回邮件。选它而不是 `net/smtp`，是为了正确的地址与信头编码——**这一处做错，就是一个被构造出来的收件人变成额外的信封命令**。 |
| `github.com/pressly/goose/v3` | 作为**库**而不是 CLI 使用，所以迁移在启动时执行，没有单独的工具需要随发布携带或运行。 |
| `github.com/go-ldap/ldap/v3` | 与上面那个目录讲 LDAP。纯 Go，所以它对部署的代价是零：没有 OpenLDAP 客户端库要装，`scratch` 容器照样能用。 |
| `github.com/xuri/excelize/v2` | 读写批量导入的工作簿，以及通讯录导出。 |
| `github.com/golang-jwt/jwt/v5` | 签发与校验访问令牌。 |
| `github.com/zitadel/oidc/v3` | OpenID Connect 的两半。给信任 Portico 的应用签发，也（通过它的 relying party 那一半）消费 Portico 所信任的外部提供方的令牌。**刻意用同一个库**：ID 令牌校验出错不是「答案不对」，是**认证被绕过**，而手写时漏掉的往往是最隐蔽的那几项——从不比对 `iss`，或者从令牌里读 `alg`。 |
| `golang.org/x/oauth2` | 上面那个 relying party 底下的授权码交换。从 Portico 开始让人经由第三方提供方登录起，它由传递依赖变成了直接依赖。 |
| `github.com/prometheus/client_golang` | 指标注册表与暴露处理器。不增加运行时依赖：`PORTICO_METRICS_ADDR` 未设时，它注册的采集器无人读取，也不打开任何监听。 |
| `sqlc` | 开发期从 SQL 生成代码。贡献者只在改查询时才需要它；生成的代码已提交。 |

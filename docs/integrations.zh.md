# 外部依赖

本项目在运行时依赖的第三方平台、API 与服务。

## 运行时服务

### PostgreSQL —— 必需

唯一的硬依赖。测试用的是 17 版；14 及以后应该都能用。

早期版本把所有东西存在一个 SQLite 文件里，那让一次部署等于一个进程加一个卷。多租户
和面向公网的 SSO 改变了这个权衡：**隔离需要真正的约束，而单写者数据库对一个别人指望
它可用的身份提供方来说是错误的形状。**

完全通过 `PORTICO_DB_DSN` 配置。**没有默认值**——别人家数据库的连接串不是可以猜的
东西。

### SMTP —— 密码找回与注册确认所必需

两者都要发消息，所以都需要一条能发出去的通道；**一个要求新账号确认地址的租户，在没有
配置中继时无法打开那个开关，并且会在打开的那一刻被告知**。Portico 讲的是标准 SMTP，
而不是某个厂商的 SDK：一个自托管的部署应该能指向它本来就在跑的任何东西——公司中继、
Amazon SES、Postmark、Resend，或者一个本地 Postfix。

**没有需要注册的厂商账号，本项目也不持有任何 API key。**

| 配置项 | 含义 |
|---|---|
| `PORTICO_SMTP_HOST` | 中继主机名。为空表示邮件找回不可用，这是默认值。 |
| `PORTICO_SMTP_PORT` | 默认 `587`。 |
| `PORTICO_SMTP_USERNAME` / `PORTICO_SMTP_PASSWORD` | 两个都不填表示不认证直连，这对私有网络里的中继是常态。 |
| `PORTICO_SMTP_FROM` | 信封与信头的发件人。一旦设了 host 就必填。 |
| `PORTICO_SMTP_ENCRYPTION` | `starttls`（默认）、`tls` 或 `none`。 |
| `PORTICO_PUBLIC_URL` | 那些消息里的链接指向哪里。 |

**STARTTLS 是强制的，而不是"尽力而为"的。** 尽力而为的 STARTTLS 可以被路径上的任何
人剥掉，而这些消息里带着密码重置链接——**一次静默降级就是全部的威胁**。

**任何凭据都不属于这个仓库。** `.env.example` 里只有变量名。

### 短信 —— 可选

用手机号找回密码需要一个短信网关，而与邮件不同，它没有一个通用协议。Portico 定义了
一个小的 provider 接口；由部署方提供实现，或者干脆关掉短信、只用邮件。

*状态：接口和一个空实现存在；具体的 provider 尚未编写。*

### Active Directory 或 OpenLDAP —— 可选，也是唯一由 Portico 主动去连的那一个

目录连接器会从一个 AD 或 OpenLDAP 里读账号。**它是唯一一个由 Portico 打开连接、去连
别人运行的系统的集成，也是唯一一个 Portico 要保存一份"日后还要拿来用"而不只是"用来
校验"的凭据的集成。**

没有厂商账号、也没有东西要买：那是你自己的目录，而要用的账号是你在里面创建的一个
**只读服务账号**。Portico 从不向你的目录写入，所以**一个有写权限的 bind 账号是一份
没有任何收益的长期风险**。

| 配置项 | 含义 |
|---|---|
| 服务器地址、bind DN、bind 密码、base DN、过滤器、属性映射 | 按连接器配置，在控制台 **目录对接** 里——**不是环境变量**，因为一次部署可能有好几个。 |
| `PORTICO_ENCRYPTION_KEY` | 32 字节十六进制。凡是**必须可还原、而不是只需可校验**的凭据，都用它做 AES-256-GCM 封装：目录的 bind 密码，以及 webhook 订阅要发送的自定义头的值。**不设它时，这两样的保存都会被拒绝**，而不是明文存下去。必须与 `PORTICO_JWT_SECRET` 不同。 |

诚实地说明那层加密的边界：**任何能读取进程环境的人都能读到这个凭据。** 它防的是真正
会发生的那种泄露——一份备份、一个副本、一个为了排障交给别人的快照。

**它是一个数据源，不是一条登录路径。** 密码从不从目录读取、也从不写入目录；一个同步
进来的账号**无法**用它的 AD 密码通过认证。联邦登录是另一个功能，目前不存在。
[目录对接](ldap.md) 里有属性映射表，以及一次同步**拒绝**做什么的清单。

### Prometheus —— 可选，而且是它来取

设置 `PORTICO_METRICS_ADDR` 会打开第二个监听，以文本暴露格式发布指标。**没有账号、
没有令牌，除了地址之外没有任何配置**：Prometheus 来抓 Portico，所以什么都不会被发出
去，也不持有任何凭据。

**方向就是要点。** 这不是遥测——除非你网络内部有东西过来读，否则什么都不会出去；而
如果你从不设那个地址，这个监听根本不存在。为什么它是一个独立端口，见
[访问指南](access-guide.md#指标)。

## 别的没有了

没有消息队列、没有缓存、没有对象存储。**也没有外部身份提供方**：上面那个目录是被
**读取**账号的，从不被要求为任何人做认证，所以**没有任何一次登录会离开这个系统**。

**什么都不会主动往外报。** Portico 只发起三类出站连接，且全都指向你配置的地址：你的
数据库、你的 SMTP 中继，以及一个你指定的目录。Webhook 加上第四类，指向租户管理员注册
的目的地——限定为公网 HTTPS，并在建立连接时再校验一次，所以它们无法被瞄准内网。指标
端点由你的监控来读，从不被推送出去。

## 新增一个

如果将来某次改动引入了一个外部依赖，**在同一个提交里**把它加到这里，写清：它是做什么
用的、怎么认证、账号归谁、成本多少、需要哪些环境变量。同时把那些变量加进
`.env.example`。

## 值得一提的构建期依赖

它们不是第三方**服务**，但因为影响部署形态，值得点名。

| 依赖 | 为什么重要 |
|---|---|
| `github.com/jackc/pgx/v5` | PostgreSQL 驱动，经 `database/sql` 使用。纯 Go，所以二进制仍可自由交叉编译，并能在没有 libc 的 `scratch` 容器里运行。 |
| `github.com/wneessen/go-mail` | 构造并发送找回邮件。选它而不是 `net/smtp`，是为了正确的地址与信头编码——**这一处做错，就是一个被构造出来的收件人变成额外的信封命令**。 |
| `github.com/pressly/goose/v3` | 作为**库**而不是 CLI 使用，所以迁移在启动时执行，没有单独的工具需要随发布携带或运行。 |
| `github.com/go-ldap/ldap/v3` | 与上面那个目录讲 LDAP。纯 Go，所以它对部署的代价是零：没有 OpenLDAP 客户端库要装，`scratch` 容器照样能用。 |
| `github.com/xuri/excelize/v2` | 读写批量导入的工作簿，以及通讯录导出。 |
| `github.com/golang-jwt/jwt/v5` | 签发与校验访问令牌。 |
| `github.com/prometheus/client_golang` | 指标注册表与暴露处理器。不增加运行时依赖：`PORTICO_METRICS_ADDR` 未设时，它注册的采集器无人读取，也不打开任何监听。 |
| `sqlc` | 开发期从 SQL 生成代码。贡献者只在改查询时才需要它；生成的代码已提交。 |

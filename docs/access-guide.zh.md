# 访问指南

怎么访问一个正在运行的 Portico 实例、凭据从哪里来，以及每种角色实际能做什么。

## 入口

| 是什么 | 地址 | 说明 |
|---|---|---|
| Web 界面 | `http://<host>:8410/` | 与 API 由同一个进程提供 |
| API | `http://<host>:8410/api/v1/` | 见 [api-conventions.md](https://github.com/Paraview-RD/portico/blob/main/docs/api-conventions.md) |
| 存活探针 | `http://<host>:8410/api/v1/health` | 无需认证。只要进程活着就应答，**刻意不碰数据库**——原因见下 |
| 就绪探针 | `http://<host>:8410/api/v1/ready` | 无需认证。本实例能连上数据库时 200，连不上时 503 |
| OpenID 发现 | `http://<host>:8410/.well-known/openid-configuration` | 默认租户。其它租户在 `/t/<code>/…` |
| SAML 元数据 | `http://<host>:8410/saml/metadata` | 交给服务提供方。其它租户在 `/t/<code>/saml/metadata` |
| CAS | `http://<host>:8410/cas` | 客户端里的 "CAS server URL"。其它租户在 `/t/<code>/cas` |
| SCIM 2.0 | `http://<host>:8410/scim/v2` | 目录要的那个"基础地址"。认证用 **接入 → 目录供给** 里签发的 bearer 令牌，**不是**管理员会话——见 [目录供给](scim.md) |
| 指标 | `http://<host>:9410/metrics` | **独立端口，默认关闭，且不做认证。** 见下 |

端口由 `PORTICO_ADDR` 决定（默认 `:8410`）。开发时前端还会跑一个 Vite 服务在
`:5410`，把 `/api` 代理到 `:8410`；**生产环境只有这一个端口**——除非你打开指标，
那会多一个它自己的。

## 指标

设置 `PORTICO_METRICS_ADDR`（例如 `127.0.0.1:9410`）即可发布 Prometheus 指标。
不设置就什么都不发布，也不会打开第二个监听。

**它之所以是独立监听，是因为它不做认证。** 没有任何 Prometheus 部署会对自己的抓取
做认证，所以这个生态里的每一个 exporter 都假定自己的地址只能从内部访问到。把它做成
应用端口上的一条路由，会让它**和登录页一样可达**，而且这个错误是看不见的——一份能
正常工作的抓取配置。请把它绑到只有你的监控能到达的网卡上，并且**绝不要**让它经由
提供应用服务的那个反向代理对外暴露。

值得告警的是这些：

| 指标 | 为什么 |
|---|---|
| `portico_sign_in_attempts_total{outcome="bad_credentials"}` | 跨多个账号一起上涨，就是撞库。Portico 不做限流；这是你得知"需要限流了"的方式。 |
| `portico_account_lockouts_total` | 在锁**生效**的地方计数。骤增要么是攻击，要么是策略对真人来说定得太紧。 |
| `portico_sign_in_attempts_total{outcome="password_expired"}` | 只在刚打开密码有效期时有意思——它告诉你有多少人即将同时来找你。 |
| `portico_db_connections_wait_total` | 连接池耗尽。它表现为"什么都慢、没有报错、也找不到慢查询"，而这个指标是唯一叫得出它名字的东西。 |
| `portico_http_requests_total{status=~"5.."}` | 这个 label 里是**精确的状态码**，所以只能用正则——`status="5xx"` 匹配不到任何一条序列，照它写的告警永远不会触发。客户端断连被记为 `499`，落在这个正则之外，所以这里上涨是真的。 |

每条时间序列在启动时都初始化为零，这样安静的实例上 `rate(...)` 返回的是零而不是
什么都没有——告警可以据此区分"没有失败登录"和"根本没在上报"。

**没有任何指标带租户或请求路径标签**，两者都是刻意的：它们是外部创造的值，而**一个
基数由别人控制的标签，正是指标端点变成整个进程最大产出物的方式**。

## 租户

每个账号属于**恰好一个**租户，任何账号都不能越出自己的租户。全新部署会有一个租户，
编码 `default`，首次启动时创建——登录时不指定租户就落在它上面，所以单租户部署完全
不需要知道租户的存在。

更多租户从命令行开通，因为 **API 没有一个跨租户的角色可供授权**：

```sh
export PORTICO_DB_DSN=postgres://portico:secret@localhost:5443/portico?sslmode=disable

portico tenant create --code acme --name "Acme Corp"   # 生成的管理员密码
                                                       # 只打印一次
portico tenant list
portico tenant disable --code acme                     # 拒绝登录，
portico tenant enable  --code acme                     # 不删除任何东西
```

每个租户在创建时都会有自己的管理员。非默认租户的用户登录时要带上租户编码——填进
**租户**输入框，或者用一个带着它的链接：

```
http://<host>:8410/login?tenant=acme
```

## 凭据

Portico 自己保存账号——MVP 里没有外部身份提供方。

| 凭据 | 从哪里来 |
|---|---|
| 引导管理员 | 首次启动时在 `default` 租户里创建。用户名来自 `PORTICO_INITIAL_ADMIN_USERNAME`（默认 `admin`）。 |
| 其它租户的管理员 | 由 `portico tenant create` 创建；不给 `--admin-password` 的话密码只打印一次。 |
| 引导密码 | 设了 `PORTICO_INITIAL_ADMIN_PASSWORD` 就用它。否则生成一个随机密码，并在启动日志里**只打印一次**——当场记下来，它没有被存在任何地方。 |
| JWT 签名密钥 | `PORTICO_JWT_SECRET`。不设的话每次启动都会生成一个随机密钥，**重启会静默作废所有会话**。请设置它。 |
| 其他所有人的密码 | 由管理员在创建时设定、由用户自助注册时选择，或者通过密码找回链接设置。 |

**任何凭据的值都不属于这份文件、这个仓库，或一个被提交的 `.env`。** `.env.example`
里只有变量名。

## 第一次运行

1. 启动服务。`./portico` 需要 `PORTICO_DB_DSN`；compose 则需要先导出
   `POSTGRES_PASSWORD` 与 `PORTICO_JWT_SECRET`——**两个都没有默认值**，缺哪个它就
   停下来说哪个，而不是替你填一个：

    ```bash
    export POSTGRES_PASSWORD=$(openssl rand -hex 16)
    export PORTICO_JWT_SECRET=$(openssl rand -hex 32)
    docker compose -f deploy/docker-compose.yml up -d
    ```
2. 如果你没有自己设密码，去启动日志里读那个生成的管理员密码。
3. 打开界面登录，然后在**个人中心**改掉那个密码。改密码会让你退出登录——这是预期
   行为，因为一次改密会撤销所有既有令牌。

## 密码找回

登录不了的用户从登录页请求一个重置链接。链接**只能用一次**，30 分钟后过期。

**它需要一个邮件中继。** 没设 `PORTICO_SMTP_HOST` 时，找回页面会直说，而不是接受一
个它无法完成的请求；此时唯一的回路是管理员重置密码。请设置 `PORTICO_SMTP_HOST`、
`PORTICO_SMTP_FROM` 和 `PORTICO_PUBLIC_URL`——最后这个是因为链接总得指向某处，而
一个在代理后面的服务器自己算不出那是哪里。

开发时把它指向一个本地收信器，而不是真的中继：

```sh
docker run -d -p 1025:1025 -p 8025:8025 axllent/mailpit

export PORTICO_SMTP_HOST=127.0.0.1
export PORTICO_SMTP_PORT=1025
export PORTICO_SMTP_ENCRYPTION=none
export PORTICO_SMTP_FROM=portico@example.com
export PORTICO_PUBLIC_URL=http://localhost:8410
```

邮件随后会出现在 <http://localhost:8025>，一封都不会离开这台机器。

短信找回已定义接口，但本版本没有提供方，所以登录页只提供邮箱这一种。

## 自助注册

默认关闭。**系统设置 → 开放用户自主注册**打开它，它下面还有一个复选框，要求新账号
**先确认邮箱地址**才能登录。

**除非面向可信网络，否则开放注册前先打开第二个。** 没有它，新账号上的地址就是随手
填的那个——而那个地址既是登录标识、又是密码重置链接寄往的地方，**于是有人可以用同事
的地址开户，然后收到对方的重置链接**。

它需要密码找回用的同一个邮件中继，而且**没有中继时保存会被拒绝**，而不是接受一个会
让每一次注册都卡在一封永不到达的邮件上的设置。

**打开它不影响已经注册过的人。** 他们的地址是在当时生效的规则下被接受的，而策略变更
不构成撤销访问的理由；真想那样做的管理员可以明确地把这些账号停用。

因未确认地址被拒的人会在登录时被明确告知，并可以从那个页面**再要一封**——他要输入的
是**地址**而不是用户名，因为信是往那里发的。

## 角色

MVP 里**恰好两个角色**，并且没有办法定义更多（需求 §3.3）。

### 管理员（`SUPER_ADMIN`）

什么都能做：创建/编辑用户及其资料，逐个或**批量**启停账号，重置别人的密码，从表格
**批量导入**并**导出**回表格，管理组织与用户组，注册经 Portico 登录的应用，签发目录
供给用的凭据，让其它系统订阅事件，读审计日志，改系统设置。

管理员做的每一件事都限定在他自己的租户内。**不存在跨租户角色。**

典型流程——批量接入已有用户：

1. **组织管理** → 先建好组织，记下它们的编码。
2. **用户管理** → **导入** → 下载模板、填好（`organizationCode` 一列对应第 1 步的
   编码）、上传。
3. 读逐行结果。失败的行会连行号和原因一起列出；改好那几行，**只重传它们**。
4. **日志审计** → 筛到 *注册*，确认落地了什么。

典型流程——接入一个应用：

1. **应用管理** → 选这个应用会讲的那个协议页签。
2. **注册** —— OAuth/OIDC 给它一个 client id 和回调地址；SAML 上传或粘贴服务提供方
   的元数据文档；CAS 给它的 URL 前缀。
3. 机密型 OAuth 客户端的 secret **只显示一次**。当场复制——存下来的只有哈希，所以
   拿到新的唯一办法是**轮换 secret**，而那会立即作废当前这个。
4. **对接地址** → 把 issuer、发现文档、SAML 元数据地址或 CAS 服务器地址复制进应用
   自己的配置。**这些取自正在运行的部署**，所以它们永远和实际提供的服务一致。
5. 顺手把**启动地址**和**图标**填了。两者都是可选的，都不影响登录——但**一个没有
   启动地址的应用永远不会出现在任何人的首页上**，而发现这件事的人，是一个被告知
   "这个应用可以用"却找不到它的用户。表单上已有的那些地址**都不是**启动地址：回调
   地址、断言消费服务地址、CAS 前缀，全都是协议在流程中途把浏览器送过去的地方，直接
   打开只会得到一个错误而不是应用。
6. **日志审计** → 这次注册会连同它允许的回调地址或断言消费服务一起被记录。

停用一个应用会**立即**生效——它不能再让任何人登录，它的凭据在内省和吊销端点上也不
再通过认证。什么都不会被删除，而且**没有删除这个动作**：审计轨迹指向的东西始终存在。

典型流程——交出一份通讯录副本：

1. **用户管理** → 筛到这次请求所关心的人。**导出用的是屏幕上那套筛选条件**，所以你
   看到的就是你会拿到的。
2. **导出** → 一个 .xlsx，列与导入模板相同，所以拿出去的文件可以改完再灌回来。
3. **它不带密码。** 密码那一列在，但每个格子都是空的——这不是疏漏：**导入是按位置
   读列的**（这样翻译过的表头也能用），所以一份少了那一列的导出，回灌时会让**每个
   字段整体左移一格，而且是静默的**。于是表头留着、值不留。报表里绝不能出现的是
   凭据，而一个列名不是凭据。
4. **它会被记录。** 每一次导出都会以 `USER_EXPORT` 出现在**日志审计**里，带上是谁
   导的、走了多少个账号。这是**每一个匹配账号的每一个属性经一次请求离开**——这里没有
   别的动作一次交出这么多，而"谁拷走了一份、什么时候"是**事故之后**才被问起的问题。

典型流程——一次处理很多账号：

1. **用户管理** → 勾选账号，或勾表头那个框选中**整页**。选择**按页**是刻意的：一个
   会静默把你从没滚动到过的账号也算进去的控件，配上*停用*是件坏事。
2. 在出现的操作条上选**启用**、**停用**或**调整组织**。
3. **每个账号都走单个账号那条路径**，所以规则依然成立：最后一个在用的管理员不能被
   停用、你不能停用你自己、每个账号的会话和下游 refresh token 立即失效。**多选几个
   人不是绕开这些规则的办法。**
4. 结果按账号返回。有失败的话，原因会点名是**哪一个**——去处理那几个，别把整批重来
   一遍。

典型流程——从 AD 里读账号：

1. **目录对接** → **Portico 主动读取（LDAP / AD）**页签 → 添加一个目录。填地址、
   base DN，和一个**只读**服务账号；Portico 从不向你的目录写入。
2. 选一个匹配的预设，然后**逐条对照你自己的目录核对每一个属性**。它们是预设而不是
   默认值，因为 Active Directory 和 OpenLDAP 在每一项上都不一致，**而错一项就会把
   所有人按错误字段的值导进来**。
3. 外部标识那一项是最要紧的——AD 用 `objectGUID`，OpenLDAP 用 `entryUUID`。它决定了
   目录里的一次改名在这里也是改名，而不是第二个账号。
4. **同步**，然后读那几个计数。被跳过的是没能变成账号的条目，最常见的是用户名已被
   Portico 自己拥有的某个账号占用。
5. 计数看起来对了之后，设置**自动同步**——每 15 分钟到每周一次。不设就是关的；开启
   时会立刻跑一次，而不是等到第一个间隔结束。**不要**改用 cron 去调同步接口：那需要
   把一个管理员的密码放进 cron 环境，比 bind 密码更不该那样丢在外面。
6. 保存 bind 密码需要部署上设了 `PORTICO_ENCRYPTION_KEY`。没有它，**保存会被拒绝**，
   而不是把凭据明文写下去。

完整细节，包括一次执行**拒绝**做什么，在 [目录对接](ldap.md)。

典型流程——让目录持续维护账号：

1. **目录供给** → 签发一份凭据。和客户端 secret 一样，它**只显示一次**，而且它是一
   个**租户级**令牌，能创建、更新、停用这个租户里的每一个账号——**把签发它当作它本
   来就是的那种特权动作来对待。**
2. 在目录那边，把基础地址设为上面入口表里的 `/scim/v2`，令牌作为 bearer 凭据。
3. **先推一个小的测试组。** 失败会以 SCIM 自己的错误形态返回，所以目录能把它们显示
   出来，而不是报一个笼统的失败。
4. **用户组** → 由目录拥有的组会被标记为*目录*，因为在这里做的修改可能会被下一次同
   步覆盖掉。账号在它们的 `externalId` 里带着同样的来源，但用户列表目前还不显示。

[目录供给](scim.md) 是该交给集成方的那一份；它**开篇就讲什么不被供给**，而那正是他
们动手**之前**需要知道的，不是动手之后。

**Webhook** 是第三个方向：既不是账号推进来，也不是被拉进来，而是 Portico 主动告诉
另一个系统「这里变了」。

典型流程——把账号变更告诉下游系统：

1. **Webhook** → **新建订阅**。目标地址必须是**公网 HTTPS**。回环、私有网段、
   link-local（云元数据就在那里）以及运营商级 NAT 一律拒绝，**并且在建立连接时会
   再查一次地址**——所以一个「现在解析到公网、稍后解析到内网」的域名同样不成立。
   **这不是一个可以权衡的加固选项**：它挡的是「拿订阅当跳板去够 Portico 所在的那张
   网」。
2. **签名 secret 只显示一次。** 它不可找回——但与客户端 secret 不同，它也**没有被
   哈希**，因为它是用来**产生**签名而不是用来校验来访者的。这对备份意味着什么，见
   [备份与恢复](backup-and-restore.md)。
3. **在接收方动手写处理逻辑之前**，把 [Webhook](webhooks.md) 交给他们。那里的校验
   示例按 `,` 切分 `X-Portico-Signature`,**而这个细节不是装饰**——见下面的轮换。
4. **投递记录**显示尝试了什么、对方回了什么、试了几次。**五次尝试摊在大约半小时
   里**，然后标记为失败；记录保留三十天。这就是把「我们根本没发」和「你的端点连着
   五次回 500」区分开的那块屏幕，**而且不需要请接收方去翻他们自己的日志**。
5. **停用**会停止投递并保留订阅与它的历史；**删除**留给「这个集成已经不存在了」。

**轮换 secret 会对接收方提出要求。** 一次轮换签发新密钥，并让旧的**再存活二十四
小时**；在这期间**每一次投递携带两个签名，逗号分隔**，任一验证通过即可。**把整个
头当作单个字符串去比较的接收方，在有人轮换之前一直工作正常，轮换之后开始拒绝一切
——而它自己看起来是健康的。** 控制台在开始轮换前会讲这件事；这里是同一句话，给读
文档而不是读界面的人。

**自定义头需要 `PORTICO_ENCRYPTION_KEY`。** 一个订阅可以发送自己的头，给网关后面
的接收方用——它想要一个自己的 `Authorization`，而**签名回答的是「这个请求体是谁
产生的」，那不是网关在问的问题**。头的值是凭据，所以用**与目录 bind 密码同一把
密钥**封装，**没有设这个变量时保存会被拒绝**，而不是把值明文写下去。它们从不回传：
API 和这块屏幕只报头的**名字**，这样既回答了「这个订阅在发什么」，又不会让一个列表
变成读取该租户全部凭据的入口。**会改变投递本身是什么**的头——签名头、
`Content-Type`、`Host`——在注册时就被拒绝。

### 普通用户（`USER`）

登录后落在**首页**：所属租户里注册过、且有启动地址的那些应用，自己账号的概览，最近
几次登录，以及密码即将过期或者没有可用于找回的地址时的提示。从那里进**个人中心**
——资料、密码，以及以自己身份登录着的设备（任何一个都可以就地结束）。

**资料**是一个账号描述性的那一半——姓名分段、职务、部门、语言、地址，也就是目录会
保存的那些字段——由每个人自己维护。它**够不到决定性的那一半**：不是角色、不是状态、
也不是所在组织。这不是靠界面藏起控件来实现的规则；**描述一个人和决定他的访问权限
是两个不同的端点，而他能调用的那个没有任何办法携带角色**。他的**直属上级**也在这条
线的另一侧：汇报关系是一项组织事实，下游系统会把它当审批链来读，所以由管理员设置。

这两个入口就是全部导航。手敲一个管理端地址会显示首页，地址栏也会被纠正过来——但那
只是个便利，**不是边界**：无论界面显示什么，服务端对管理端调用一律回 `ADMIN_REQUIRED`。

首页上的应用是**这个租户的，不是他本人的**，而且页面明说了这一点。本版本只有两个固
定角色、没有"谁可以用什么"的概念，所以每个人的列表都一样；**没有那句话，读者会合理
地得出"同事首页上没有的应用，是那位同事没被授予"的结论。**

自助注册的账号一律是这个角色，注册时无法申请别的。

**注销账号。** 任何人都可以在**个人中心**注销自己的账号，需要用密码确认。这是**唯一
允许自我停用的地方**——其它每一处都会拒绝，这样管理员不会不小心把自己锁在外面。

它是**停用而不是删除**：账号不能再登录，每一个会话和每一个联邦 refresh token 立即失
效，而审计轨迹指向的账号依然存在。**管理员可以把它恢复**——启用这个账号即可，同时会
清掉注销标记；**已经结束的会话仍然是结束的**。租户里最后一个在用的管理员**不能**注
销自己，因为不会再有人能把它撤销。

一个注销后又来登录的人，会被告知账号**已注销**，而不是被停用——这两者需要不同的应对，
而用户列表里能看出发生的是哪一种。

## 对外暴露之前

Portico 提供的是明文 HTTP，并且**不做请求限流**。两者都是刻意的——它把这些交给反向
代理而不是自己再实现一遍——但这也意味着，**对任何 localhost 之外可达的部署，代理是
必需的而不是可选的**。原因见
[SECURITY.md](https://github.com/Paraview-RD/portico/blob/main/SECURITY.md)。

随附的 compose 文件绑定在 `127.0.0.1` 上，所以默认配置不会被直接访问到。

### nginx

```nginx
limit_req_zone $binary_remote_addr zone=portico_auth:10m rate=10r/m;

server {
    listen 443 ssl http2;
    server_name id.example.com;

    ssl_certificate     /etc/letsencrypt/live/id.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/id.example.com/privkey.pem;
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;

    # 只对凭据相关端点限流；其余都已经过认证。
    location ~ ^/api/v1/auth/(login|register)$ {
        limit_req zone=portico_auth burst=5 nodelay;
        proxy_pass http://127.0.0.1:8410;
        include /etc/nginx/proxy_params;
    }

    location / {
        proxy_pass http://127.0.0.1:8410;
        include /etc/nginx/proxy_params;
    }
}
```

### Caddy

```caddyfile
id.example.com {
    @auth path /api/v1/auth/login /api/v1/auth/register
    rate_limit @auth {
        zone portico_auth {
            key    {remote_host}
            events 10
            window 1m
        }
    }
    reverse_proxy 127.0.0.1:8410
}
```

任一方案就位后，设置 `PORTICO_TRUST_PROXY_HEADERS=true`，这样审计日志记录的是真实
客户端地址而不是代理的地址。**没有代理时不要设它**：否则调用方可以伪造记在自己名下
的 IP。

## 值得知道的几道护栏

- **账号永不删除。** 停用是它的替代品，这样审计轨迹保持完整。被停用的用户立即退出
  登录。
- **最后一个管理员不能被停用或降级**，任何人也不能停用自己的账号。这两件事一旦发生，
  除了直接动数据库之外无法挽回。
- **注册默认关闭。** 需要时在**系统设置**里打开；一个在有人完成配置之前就被暴露出去
  的实例不会接受注册。
- **组织是一棵树。** 创建时设上级，或者之后改上级来重排——**编码保持不变**，因为下游
  系统可能已经存了它。会把一个组织挪进它自己分支里的移动会被拒绝；**外键抓不到这种
  情况，因为环里的每一行单独看都是合法的。**
- **停用一个组织**会阻止新成员加入，但保留现有成员。它**不会**向下级联，子组织维持
  原样。
- **退出登录只结束这一个会话，不是全部。** 笔记本和手机是两次不同的登录；**个人中心**
  里的**退出所有设备**才是把两者都结束的那个。个人中心也会按收到的原样列出当前以你
  身份登录的地址和浏览器，并允许你结束其中任何一个。管理员可以从用户列表里查看并结束
  某个用户的会话——电话那头一句"我觉得我的账号被盗了"，需要的就是这个。**联邦会话是
  这一切的例外**：在任何地方退出都会结束全部联邦会话，因为退出一个单点登录系统会被
  理解为同时退出那些应用。每种协议下这到底能到达什么、到达不了什么，见
  [单点登录](federation.md)。
- **一个重置链接会结束所有会话。** 完成找回就是改密码，而改密码会撤销每一个有效令牌
  ——**这正是要点**，因为需要找回的原因往往是密码已经在别人手里。
- **再要一个链接会让前一个失效。** 只有最新的那个能用。
- **密码规则按租户配置，在系统设置里**，而且大多默认关闭。最小长度 8 是**任何策略都
  不能下调的下限**。复杂度要求（大写、数字、符号）、重复使用检查和有效期都提供，且默
  认关闭——**它们让密码更容易被猜中而不是更难**，之所以提供是为了那些被要求它们的合规
  审计。如果你有选择权，请改为提高最小长度。
- **过期的密码根本无法登录。** 它不会产生一个带"必须改密"标记的会话，因为**标记是
  API 客户端可以忽略的东西**。登录页会就地要求换一个新的。
- **没有任何东西跨越租户。** 用户、组织、审计条目和设置都属于某一个租户，一个租户的
  管理员看不到也改不了另一个的——**包括按 id、包括自己发一个租户头**。任何地方都不存
  在能做到这件事的账号。
- **存活探针指向 `/api/v1/health`，就绪探针指向 `/api/v1/ready`，不要都指向同一个。**
  `/health` 只要进程在跑就应答，并且**刻意从不碰数据库**：数据库故障不会因为重启实例
  而修好，而一个跟着它一起失败的存活探针，会在最糟糕的时刻把一个依赖故障变成整个集群
  的重启风暴。数据库检查属于 `/ready`——故障期间正确的回答是"别再给我发流量"，不是
  "把我重启"。

- **审计日志默认永久保留，除非你另行指定。** 系统设置里有一个按天的保留期；默认的 0
  表示全部保留。其它值至少为 7，超期的条目会被每小时的清理任务**永久删除且不留副本**。
  产品里没有别的东西会删除审计条目。

## 接入一个下游系统

下游应用拿到用户的令牌后调用：

- `GET /api/v1/users/me` —— 用户的资料与组织，这是创建或更新一条本地记录所需的全部
  信息（需求 §3.8.2）。
- `GET /api/v1/auth/permission-check` —— 这个调用方是不是管理员，用于给下游系统自己
  的管理界面做门禁。

两者用的都是**用户自己的** bearer 令牌。MVP 里没有服务账号，也没有机器对机器的凭据。

这条路径适合本来就持有用户 Portico 令牌的系统。**需要自己让人登录的系统应当改用
OpenID Connect**——把它的库指向 issuer，并用 `portico client register` 注册它。见
[单点登录](federation.md)。
